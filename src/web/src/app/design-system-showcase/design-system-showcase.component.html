Field

Label, hint, required, error, warning, disabled, and every projected control type.

The control is projected, so no template binding can reach it — the field wires aria-describedby to its hint, error and warning, aria-invalid while an error shows, and aria-required when required, after each render. Without that the * and the hint are visible and invisible at once. Optionality is the inverse and is stated once per form: marking one optional field among a dozen unmarked ones makes the rest read as required. A warning is advice and never marks the control invalid.

Focus ring

One token and one rule — outline: 3px solid var(--cp-focus) at an outline-offset of 2px, on :focus-visible in global.css. The ring is opaque, because a ring mixed with transparent takes the lightness of whatever is under it and measured 1.66:1 on the light page. Tab along the row in both themes: the ring holds at least 3:1 on the page, on a white sheet, on a soft fruit tint, and inside a cp-card, which is a dark sheet in the dark theme and reads the page's own ring.

A focused primary button is green fill, 2px of page, green ring. The ring is the same colour as the fill it haloes; the page showing between them is what separates the two, at 5.05:1 in the light theme and 8.70:1 in the dark. Inside a card it is the card showing between them, at 5.35:1 and 7.67:1.

Combobox

A text input that filters a list it is given, with the WAI-ARIA combobox keyboard: arrows to move, Home/End to jump, Enter to choose, Escape to close without losing what was typed. Focus never leaves the input — the active row is named by aria-activedescendant — and the number of remaining rows is announced. It fetches nothing; a consumer filtering server-side passes its own list with [filterLocally]="false".

It renders no label of its own: it composes inside cp-field, which owns the label, hint and error, and whose input styling reaches the text box inside it.

A caret marks it as a picker, and clicking the box opens the list — without both, a combobox wearing cp-field's ordinary input styling is indistinguishable from a text box, and a creator who clicks it and waits concludes the picker is missing. Focus alone does not open it: tabbing through a form would pop every list open on the way past and announce a count nobody asked for.

Restricted: text that names no unit reverts when the field is left, so the box only ever reads as the unit it stands for. Chosen: {{ unit()?.label ?? 'nothing yet' }}.

Checkbox

A drawn control, because an unstyled <input type="checkbox"> is painted from the inherited color-scheme — in dark mode its unchecked box is a dark filled square — and arrives at 13×13 with no author focus ring. The real input is still there, focusable and announced; it is only visually replaced. Checked reads as a glyph, so the state does not depend on telling two colours apart, and the whole label is a 40px target.

Choice group

A set of answers as selectable tiles. The whole tile is the target, which is how an option carrying a label, a line about what it means and a sample sentence stays scannable — and how it clears 40px without each feature inventing padding. Drawn, for the same reason the checkbox above is: a native radio left to the inherited color-scheme arrives at 13px with no author focus ring. The real input stays in the DOM, so arrow keys, Space and what a screen reader says are all still the browser's.

Several answers, capped: at the cap the rest are disabled rather than a pick being dropped silently, so the limit is visible before it bites.

Short options take the width they need and wrap, rather than stacking.

Validation summary

Everything wrong with a form in one place, each line a button that takes the creator to its field. Errors are headed with their count and stop a save; warnings and information sit below under their own heading and never do. Severity is a glyph as well as a colour — a disc, a triangle, an i. It decides nothing: the form says which issues exist and what selecting one does. Try it: save with the title empty, then set the servings above 40 to see a warning appear while typing.

Anchor nav

Ordinary navigation over a document that is all present — every item tabbable in order, no roving tabindex, deliberately not a tablist. It emits which destination was asked for; scrolling and focus stay with the consumer, which is the only side that can name the control worth focusing. With no items it renders nothing at all, so a surface with one section shows no empty shell.

Set --cp-anchor-nav-direction: column on the host — from inside a container query, typically — to stack it in a gutter. The default wrapping row is what fits above the content it names on a narrow screen and at 200% zoom.

Live status / toast

Info/success auto-dismiss after 5s and pause on hover; warning/error are persistent until dismissed.

Form section

One named part of a form: a heading, a sentence under it, the server's word on the whole part when it refuses, and the fields themselves. Every form in the app is built from these, stacked a --cp-space-8 apart, so a long form reads as named parts rather than a wall of boxes.

The section names itself from its own heading and, while a problem is showing, is described by it — so a form that moves focus here on a refusal reads the heading and then the reason. Fields projected straight into it are capped at --cp-measure-field; a field inside a component projected here is left to that component. Short fields share a line by going into a cp-field-row; give it columns when they are quantities, so the row stays inside the line the other fields keep to and each value is an equal share of it.
